
# 蒙泰RIP模块开发文档

version 2.55.0, 2026.6.2 by 姚诚成

## 1.概述

蒙泰RIP模块提供了对pdf, ps, eps, 图像文件的rip, 颜色处理，挂网和驱动输出功能。其中支持的图片格式为:

bitmap

jpeg

Photoshop PSB

Photoshop PSD

png

tiff(支持BigTIFF)

webp

自v1.12.0始, 开始支持imagePlugin, 从而客户可以支持其它图片格式或是私有格式图片.

支持平台:

Windows x86, Windows 10及以上版本

Windows x64, Windows 10及以上版本

Linux x64

Linux arm64(不支持pdf,ps,eps)

模块名称为mtrip, API接口函数为

<<<PRE 0>>>
const void* MainTopRip(const void *data, size_t *size);
void MainTopRipCancel();
void MainTopRipReleaseBuffer(const void *buf);
void MainTopShutdown();

<<<END PRE>>>

 | API
 | 说明

 | MainTopRip
 | 使用data传入json格式的配置数据, utf-8编码. size为data数据的字节数. 函数执行完毕，返回json格式的响应字符串指针，size为返回的数据字节数.

 | MainTopRipCancel
 | 取消MainTopRip正在处理的操作(扫描, rip)等, 等MainTopRip实际被取消后返回。

 | MainTopRipReleaseBuffer
 | 释放由MainTopRip返回的字符串空间. MainTopRip返回的合法字符串(不为nullptr时), 使用完毕必须经过释放.

 | MainTopShutdown
 | 在应用退出之前执行，用于清理蒙泰RIP模块使用的缓冲等数据。在执行完毕MainTopShutdown后，不要再执行任何蒙泰RIP模块API.

MainTopRip主要支持如下几种操作命令:

queryMode 用来查询当前打印机支持的模式

queryFile 对文件基本信息进行查询

rip 实际做rip输出

query 查询信息

config 配置

preview 预览

colorCorrection 校色信息

job 作业操作

支持的返回码:

  成功

  用户取消

  输入参数错误

  没有找到相应的prs

  错误的prs文件

  不支持的输入文件格式, 比如不是ps,eps,pdf,图像格式等

  打开输入文件失败

  解析输入文件失败: 输入文件错误

  模块忙。ps,eps.pdf使用的解释器，只有一份实例(既用于扫描也用于实际rip), 图像格式的扫描和输出支持多实例。

  不支持的命令

  内存不足

  图像驱动或输入插件加载失败

  创建输出对象失败: 创建输出文件失败, 加载输出插件失败, 输出插件Start失败等

  加载输出驱动失败

  需要的组件加载失败, 可能是安装错误

  图片数据或输入插件读取错误: 可能是图像文件内容错误

  无ripServer加密锁或是非ripServer加密锁

  加密锁已过期.

  加密锁计时芯片损坏.

  作业尺寸或精度需求超过了加密锁限制.

  颜色模块失败，可能是需要的icc等找不到.

  通过http访问时，成功启动了作业，但是在处理中.

  输出失败，包括file,raw,plugin等方式的数据发送失败.

  作业不存在(v1.8.0始)

  插件不存在(v1.8.0始)

  通过mtripNet代理访问错误. 比如连接服务器失败等. 返回信息中添加error字段描述错误原因.(v1.8.0始且使用mtripNet代理)

  contone设置的参数目前不支持.

  clip参数错误.

v2.0.0版本起支持的错误码返回码如下(值从0x01000001开始)

0x01000001. 输入失败，包括file,plugin等方式的数据读取失败.

0x01000002. 输入插件加载错误.

0x01000003. (v2.7.0始)图像变换模块创建失败.

0x01000004. (v2.7.0始)图像变换失败, 可能是参数配置有误.

0x01000005. (v2.20.0始)当前无校色数据, 查询或编辑校色时可能的返回.

0x01000006. (v2.24.0始)缺少自定义输入范围.

0x01000007. (v2.41.0始)自动排版失败.

0x01000008. (v2.41.0始)加密锁不支持自动排版.

0x01000009. (v2.42.0始)驱动不支持点类型统计功能.

文件类型的输出参数:

 | mode

 | 指定输出ip

 | 连接服务器超时, 以毫秒为单位。可缺失，表示1050

plugin类型输出，客户自行提供输出插件进行输出.

 | 属性
 | 类型
 | 最低版本
 | 说明

 | lib
 | string
 |
 | 插件动态库路径.

 | id
 | int
 | v1.12.0
 | 插件id, 和lib互斥. 都存在情况下优先使用id.

 | param
 | string
 |
 | 传递给plugin.Start的param, 可以缺失.

分页文件类型的输出参数:

 | 属性
 | 类型
 | 说明

 | name
 | string
 | 输出文件名. ripserver会在输出文件名后自动添加"-n"的后缀以表征输出的页码.

 | mode
 | int
 | 文件模式, Windows下忽略

每次输出, rip模块都会重新加载plugin动态库. 并在输出结束时释放. 为了防止频繁的加载操作，如果是连续输出情况下，客户程序可以先加载plugin模块，并在退出时释放，从而避免频繁的实际加载.

v1.12.0及以后版本，连续多任务输出，可以使用regPlugin进行注册输出插件, 使用id来指定插件。在退出前使用unregPlugin来注销插件或是让mtrip来自己清理插件.

### 1.2 实例说明

对于pdf,ps,eps的解析和图片的解析有不同的实例限制.

pdf,ps,eps只有一个共用解析器，后续的作业在前面作业没有完成扫描或是rip时，后续作业无法进入。实在要进入，将返回busy.

图片解析使用各自的解析器, 无特殊实例限制，即使上一个pdf,ps,eps作业没有解析完毕或是上一个图片没有解析完毕，仍然可以解析下一个图片。

### 1.4 作业进度通知

v2.4.0版本中合并了作业进度功能, 作业进度可以通过查询方式进行获取. 或者通过注册进度通知插件进行侦听通知.

当作业在rip时指定id时, 作业完毕后, 作业进度信息并不会立即删除, 会保留大致5分钟左右时间备查.

可以注册多个不同的进度插件，进行多份通知。

注意事项: 不保证所有的进度都会连续通知到, 特别是在作业比较小时. 比如收到5%的进度, 可能下个收到的通知就是99%, 再下一个收到的就是End succeedfully了. 规则是: 有一个待通知的项，比如进度5%, 在后面一个通知到达而前面的通知还没有发送出去时, 前面的通知废弃, 直接发送后面的通知.

### 1.5 白墨通道定义

v2.4.0版本开始, 支持挂网后白墨通道功能,

建议使用inputColorEditor来生成自定义专色, 该标签不再维护, 后续可能废止.

每个通道具体定义方式如下：

 | 属性
 | 类型
 | 说明

 | mode
 | string
 | 通道模式, 其可以的定义值如下：none：无, 通常不使用, 会忽略该通道数据
full：全部, 全范围出墨
color：填充底色, 有墨水的部分出白墨
seperate：反铺：无墨水的地方出白墨
spot：根据spotName标签指定专色通道出白墨

 | spotName
 | string
 | 指定专色通道名称, 如"W1", 当mode标签为spot时有效.

 | density
 | string
 | 指定输出的白墨墨量大小, 可指定为如下方式：normal：正常
less：减墨量
small：最小墨量
more：增墨量
most：最大墨量
ownset：自定义墨量, 由densityValue标签指定具体墨量大小

 | densityValue
 | int
 | 指定自定墨量大小, 范围[0, 100], 当density标签为ownset时有效.

### 1.6 额外通道定义

v2.11.0版本开始, 用于定义驱动以外的额外通道. 此处定义的通道会在挂网前生成.

建议使用inputColorEditor来生成自定义专色, 该标签不再维护, 后续可能废止.

每个通道具体定义方式如下：

 | 属性
 | 类型
 | 说明

 | mode
 | string
 | 通道模式, 其可以的定义值如下：full：全部, 全范围出墨
color：彩色全铺, 有彩色的位置定义最大值
smooth：彩色平滑, 以彩色计算灰度值定义

 | invert
 | string/int
 | 数据是否取反, 可以是"true"/"false"的字符串定义，也可以是0,1(int类型). 可以缺省, 默认为0.

 | inkName
 | string
 | 通道名称, 如"W1", 可以缺省, 会以一个默认名称定义通道.

### 1.7 墨量控制定义

v2.12.0版本开始, 墨量控制用于新增或调节通道的墨量相关参数, 即修改以prs文件为模版定义的部分驱动数据.

具体相关定义如下：

 | 属性
 | 类型
 | 说明

 | mode
 | string
 | 模式, 其可以的定义值如下：edit：编辑相关通道, 使用index标签定义通道索引
new：新增通道, 用于定义驱动未指定的通道

 | index
 | int
 | 通道索引, 用于定义需要修订的通道索引号, 从0起, 当"mode"为"edit"时有效

 | inkName
 | string
 | 墨水名称, 用于定义新增通道的墨水名称, 当"mode"为"new"时有效

 | maxInk
 | float
 | 最大墨量, 取值范围[0.0, 100.0], 可缺省, edit模式下默认使用prs定义值, new模式默认为100.0

 | singleGamma
 | float
 | 通道伽马值, 取值范围[-3.0, 3.0], 可缺省, edit模式下默认使用prs定义值, new模式默认为0.0

 | linear
 | float array
 | 线性化曲线, 必须包含256个元素, 每个元素取值范围[0.0, 1.0], 可缺省, edit模式下使用prs中定义曲线, new模式下使用[ 0.0/255.0, 1.0/255.0, 2.0/255.0, ... , 254.0/255.0, 255.0/255.0, ]

### 1.8 输入颜色编辑

v2.14.0版本开始, 可用于在校色前定义新的专色通道, 每个通道定义方式和extraMap类似, 具体如下：

 | 属性
 | 类型
 | 说明

 | string
 | 通道模式, 其可以的定义值如下：full：全铺. 全范围出墨

### 4.2 mtripNetProxy

mtripNet的代理动态库，用于和mtripNet连接并可发送作业到mtripNet. 在开发阶段，由于mtrip.dll禁止了调试，可以手动修改mtripNetProxy.dll名称为mtrip.dll, 从而在调试状态运行。

mtripNetProxy.dll不依赖于开发包的其它可执行文件，其使用HTTP或GRPC与mtripNet进行通信。

除标准的MainTopRip, MainTopRipCancel, MainTopRipReleaseBuffer导出函数外, mtripNetProxy.dll额外提供了两个新的函数:

<<<PRE 2>>>
typedef void (* progressProc)(MainTopJobProgress *p);
void MainTopSetHostPort(const char *hostName, int port, int protocol);
int MainTopSetJobProgressCallback(progressProc callbak);

<<<END PRE>>>

其中MainTopSetHostPort用于修改默认的连接地址、方式. 默认hostName为localhost, port为8089, 使用HTTP方式连接. protocol支持0: HTTP; 1: GRPC

MainTopSetJobProgressCallback用于注册一个作业进度通知回调。可以不使用，从而不使用回调. 返回值0表示失败, 其他值成功.
